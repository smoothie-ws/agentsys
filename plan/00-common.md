# Дорожная карта AI-контроллера: общее (читать перед любым этапом)

Этапы лежат в соседних файлах `01-…` … `06-…`. Каждый этап можно отдавать исполнителю отдельно, но вместе с этим файлом. Дополнительно читать `claude/working-agreements.md`, `claude/engine-design.md`, `claude/signal-engine.md`, `claude/flow-control.md`.

## Правила проекта (из working-agreements)
- Проект на раннем этапе. Никакого легаси и обратной совместимости: без миграций старых форматов, без deprecated-алиасов, без fallback на старое поведение. Заменяешь способ — старый удаляешь целиком: код, тесты, документацию, данные в `data/` и `builtin/`.
- Один единообразный способ сделать вещь (пример: выходы Custom-узла задаются только через `node.output.<name>`).
- Живые данные пользователя в `data/` приводить в соответствие с изменениями.
- Изменения не коммитить без просьбы пользователя.

## Как устроена система (кратко)
- Браузерное приложение плюс маленький Node-сервер `server.js`; данные в `data/*.json`; слой хранения `js/storage/db.js` (DB: key-value с кэшем в памяти, JSON-файлы под сервером, IndexedDB без него). Безголовый запуск и загрузчик для тестов: `headless.js`.
- Движок сигналов: данные текут по проводам и читаются по требованию, «действие» идёт сигналами (тип `signal`). `compilePlan(snapshot, roots, ...)` даёт plan (plain data), `executePlan(plan, env)` в `js/model/executor.js` исполняет его в одном Web Worker на запуск. `runPlan` и мост `bridgeFor` — `js/backend/scripts.js`; `evaluateGraph`/`runPlanned` — `js/model/evaluate.js` (события в хуки); запуски, триггеры, планировщик (`scheduler/tick`), вебхуки — `js/backend/routes-runs.js`.
- Только два «кирпича»: Script (`op: 'script'`) и Event (`on_run`, `on_read`, `on_placed`, `on_deleted`, `on_wired`, `on_widget`). Узел Библиотеки — Complex Node (копия группы) из них. В `builtin/` лежат только провайдеры и skills.
- API скрипта: `node.input`, `node.output`, `await node.emit(name, {handles, failFast})`, `node.reread`, `node.display`, `node.widgets`, `node.flow.break/continue/cancel/abort`, `node.cancelled`, `agentsys(method, path, body, query)`, `context`.
- Лимиты: 16 параллельных, 120 с собственного кода (ожидание внутри `emit` не считается), цепочка 1000, 20 МБ на результат, 100 МБ на запуск.
- Волны (waves): каждый `emit` открывает волну, дерево как стек вызовов. Отмена кооперативная, работающий код не прерывается.
- Тесты: `node --test`; `tests/harness.js` (`createApp`, `nodes`, `fn`, `bundleOf`, `place`, `flow`). Сейчас 186 тестов, все проходят. Этап не завершён, пока весь набор не зелёный.

## Открытое допущение
Пользователь не ответил, чем должен быть контроллер: автономным агентом, который неделями сам ведёт проект, или интерактивным оркестратором, который работает, пока человек рядом. План написан под **автономного агента**; интерактивный режим — частный случай (меньше таймаутов, больше подтверждений). Если выберут интерактивный, этап 1 можно упростить (не нужна очередь, переживающая перезапуск), этапы 2–4 остаются.
