# Этап 4. Модель прав для скриптов (до того, как ИИ начнёт создавать узлы)

Сначала прочитать `00-common.md`. Желательно после этапа 3 (поток одобрений).

## Цель
Скрипт получает только те возможности, которые ему явно выданы. Иначе узел, написанный ИИ, может удалить любые данные через `agentsys(...)`.

## Что есть сейчас
`bridgeFor` (`js/backend/scripts.js`) пропускает любой `method/path` в `Backend.request`. Любой Script может править и удалять что угодно, включая узлы и Библиотеку.

## Проектное решение
1. **Capabilities** — именованные разрешения: `graph.read`, `graph.write`, `library.write`, `initiative.read`, `initiative.write:<id>`, `llm.call:<provider/model>`, `net.fetch:<host>`, `run.start`, `approval.request`, `secrets.use:<name>`. Узел Библиотеки **декларирует** нужные в манифесте (поле в `payload`).
2. **Политика** — на уровне рабочего пространства/инициативы: что вообще можно выдавать (allow-list). Итог = «заявлено узлом» ∩ «разрешено политикой» ∩ «выдано пользователем».
3. **Проверка в одном месте** — `bridgeFor` сопоставляет `method+path` с capability по таблице маршрутов (у каждого `route(...)` поле `needs`). Чего нет в таблице — запрещено.
4. **Узлы, созданные ИИ, — в карантине:** `origin: 'ai'`, по умолчанию минимальные права (чтение); повышение — через одобрение человека (этап 3) с показом diff кода и списка заявленных прав.
5. **Секреты** не передаются в код: узел просит `secrets.use:name`, мост подставляет значение в запрос, код его не видит.
6. **Сеть:** `net.fetch` с allow-list хостов; проверить и закрыть прямой `fetch`/`importScripts` в Worker (`WORKER_SOURCE`) — единственный путь через мост.
7. **Аудит:** каждое отклонённое и каждое чувствительное действие пишется в журнал запуска.

## Пошаговые задачи
1. Инвентаризация маршрутов `js/backend/routes-*.js`: каждому добавить `needs: [...]`; тест, что у каждого маршрута есть `needs`.
2. Манифест прав в payload Library-узла (+ UI: список галочек).
3. Принудительное применение в `bridgeFor`; ошибка `permission_denied` с пояснением, какое право нужно.
4. Закрыть прямую сеть и глобальные API в Worker.
5. Карантин `origin:'ai'` и поток повышения прав.
6. Секреты: хранилище, подстановка.
7. Обновить `examples/*.json` и `data/`, добавив манифесты. Без fallback «нет манифеста — всё разрешено»: отсутствие манифеста = нет прав.

## Тесты
Узел без права не пишет в граф; с `graph.read` читает, но не пишет; `net.fetch` к чужому хосту отклоняется; прямой `fetch` в Worker блокирован; AI-узел стартует с минимальными правами; таблица `needs` покрывает все маршруты.

## Документация
`docs/permissions.md`; `signal-engine.md` (`agentsys` и права); `interface.md` (редактор манифеста).

## Риски
Ломает существующие узлы — ожидаемо и допустимо по правилам проекта: обновить примеры и данные. Слишком мелкая гранулярность → ограничиться ~10–15 возможностями.

## Критерии приёмки
Ни один маршрут не доступен скрипту без явной возможности; тесты на обход (прямая сеть, глобалы Worker) проходят.
