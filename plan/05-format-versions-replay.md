# Этап 5. Текстовый формат, версионирование, тесты и воспроизведение

Сначала прочитать `00-common.md`. Replay опирается на трассу из этапа 3, версии — на права из этапа 4.

## Цель
Графы можно читать, сравнивать и ревьюить как текст; изменения откатываются; запуск можно воспроизвести без реальных моделей; регрессии ловятся автоматически.

## Что есть сейчас
Данные — JSON в `data/`, экспорт Библиотеки — `{agentsys:1, kind:'custom_node', ...}`. Нет истории версий, диффа, воспроизведения.

## Проектное решение
1. **Канонический текстовый формат** графа и узла: детерминированный JSON (стабильный порядок ключей, один узел — один блок, позиции вынесены отдельно, чтобы перемещение не засоряло дифф). Код скрипта хранится отдельным текстом (`.js`), а не строкой с `\n`. Один формат и один (де)сериализатор; старый формат экспорта удалить (без совместимости).
2. **Версионирование.** Каждое сохранение узла/графа создаёт неизменяемую версию (содержимое по хэшу) + указатель «текущая». Снимки с дедупликацией, дельты не нужны. Откат — смена указателя. Запуск фиксирует версии использованных узлов в plan.
3. **Хранение.** `data/` как каталог текстовых файлов, пригодный для git. Внешнюю БД отложить; зафиксировать критерии перехода: > N запусков/день, > X ГБ журнала, несколько одновременных писателей.
4. **Воспроизведение (replay).** `replay(run_id)`: все вызовы через мост (LLM, сеть, время, случайность) берутся из записанной трассы. `Date.now`, `Math.random` в Worker подменяются записанными значениями/сидом. Расхождение (код запросил то, чего нет в записи) — ошибка с указанием места. Порядок параллельных событий фиксируется по записи.
5. **Тесты графов.** Формат `{graph, inputs, mocks, expected}` — файл рядом с узлом; раннер подхватывается `node --test`; фальшивый провайдер (этап 3) отвечает по записанным ответам. Golden-тесты для типовых агентских сценариев; обновление эталонов — явной командой.
6. **Evals качества ИИ-узлов** — отдельно от детерминированных тестов: набор кейсов, метрики, запуск вручную/по расписанию; CI не блокирует.

## Пошаговые задачи
1. Спецификация до кода: `docs/format.md`, пример на 2–3 узлах.
2. Сериализатор/десериализатор + тест «туда-обратно побайтно стабилен».
3. Перевод живых `data/` и `examples/` на новый формат одноразовым скриптом, который затем удаляется.
4. Версии узлов, хэши, откат; UI «история» (список, дифф кода, откатить).
5. Фиксация версий в plan и в записи запуска.
6. Replay: подмена источников недетерминизма, режим `replay`, UI «воспроизвести».
7. Формат и раннер тестов графов; перевести часть `tests/flow-nodes.test.js` в него как образец.
8. Каркас evals.

## Тесты
Стабильность сериализации; откат; запуск использует зафиксированную версию, даже если узел потом изменили; replay даёт идентичный результат и падает при расхождении; раннер тестов графов.

## Документация
`docs/format.md`, `docs/versioning.md`, `docs/replay.md`, `testing.md`.

## Риски
Размер версий → дедупликация по хэшу и ретеншн. Недетерминизм сторонних источников → фиксировать по записи.

## Критерии приёмки
Любой запуск воспроизводится офлайн; диффы графов читаемы; откат узла не ломает идущие запуски.
