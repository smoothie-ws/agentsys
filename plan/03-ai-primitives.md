# Этап 3. Примитивы ИИ (тонкий слой в движке + узлы Библиотеки)

Сначала прочитать `00-common.md`. Требует этап 1 (`node.wait`, хранилище запусков).

## Цель
Вызовы моделей, бюджеты, повторы, трассировка, подтверждения человеком — явные, наблюдаемые вещи, а не код в каждом скрипте.

## Что есть сейчас
Скрипт ходит к LLM через `agentsys(...)` (провайдеры в `builtin/`). Нет бюджета, единой трассировки запросов, повторов с отступом, подтверждений.

## Проектное решение (движок знает только минимум)
В движок — только то, что снаружи надёжно не сделать:
1. **Бюджет запуска/инициативы.** Счётчики токенов, стоимости, числа вызовов и времени; хранятся рядом с запуском; проверяются на каждом вызове LLM/внешнего API через мост `bridgeFor`. Превышение — специальная ошибка `budget_exceeded`, волна отменяется, запуск уходит в `waiting`+`approval` (запросить увеличение) или `failed` — по настройке.
2. **Трассировка вызовов моделей.** Каждый вызов через мост пишет событие `llm_call`: провайдер, модель, параметры, хэш и размер prompt/response, токены, цена, длительность, ошибка. Полный текст — отдельным блобом с ретеншном и редактированием секретов. Основа воспроизведения (этап 5).
3. **Повторы и таймауты** на уровне моста: `retry: {max, backoff, retry_on}` по умолчанию для сети/429/5xx; параметры видны в трассировке, без «магии».
4. **Одобрение человеком** — на `node.wait({approval})` из этапа 1: запись `Approval {id, run_id, node, question, options, context_ref, status, expires_at}`; ответ через `POST approvals/{id}` будит запуск. UI: очередь одобрений (кнопки, комментарий). Тайм-аут и действие по умолчанию (отклонить/эскалировать) задаются.
5. **Структурированный вывод.** Проверка ответа по схеме с авто-повтором «исправь формат» (ограничено числом попыток и бюджетом).

В Библиотеку (скриптовые узлы, не в движок): `LLM call`, `LLM structured`, `Tool-use loop` (цикл «модель → инструмент → модель» на `For`/`While` и `break`), `Ask human`, `Check budget`, `Summarize/Compress context`, `Router` (выбор ветки моделью).

## Пошаговые задачи
1. Модуль `js/backend/llm.js` — единая точка вызова моделей (если вызовы разбросаны по провайдерам — свести в одну функцию; старые пути удалить).
2. Учёт бюджета: структура, хранилище, проверка в `bridgeFor` до (оценка) и после (факт) вызова.
3. Журнал `llm_call` и блобы; настройки ретеншна и редактирования.
4. Повторы/таймауты.
5. `Approval`: модель, маршруты `approvals*`, интеграция с `node.wait`, UI-очередь.
6. Узлы Библиотеки + `examples/ai-nodes.json` + тесты на детерминированном фальшивом провайдере (в `tests/`).
7. Настройки: дефолтные бюджеты, список разрешённых моделей.

## Тесты
Бюджет обрывает цикл «модель → инструмент»; повтор при 429; одобрение разрешает/отклоняет/истекает; трассировка содержит все вызовы; структурированный вывод с повтором; параллельные вызовы честно делят бюджет.

## Документация
`docs/ai-primitives.md`; `signal-engine.md` (если меняется API); `testing.md` (фальшивый провайдер).

## Риски
Гонка в учёте бюджета при 16 параллельных вызовах → списание в `exclusive`, пессимистичное резервирование перед вызовом. Утечка секретов в трассировке → редактирование по умолчанию.

## Критерии приёмки
Цикл агента с инструментами останавливается по бюджету; каждое решение модели видно в трассе; операция с одобрением переживает перезапуск.
