# Ревизия движка выполнения графа, 25 октября 2026

Задача: пройти весь путь выполнения графа (`model/evaluate.js`, запуск кода узлов в `backend/scripts.js` и `headless.js`, запуски в `backend/routes-runs.js`), упростить и ускорить его, не меняя того, что он делает. Формат данных, API и поведение узлов не менялись.

## Что показали замеры

Обход графа почти ничего не стоит: 1000 узлов и 2970 связей обсчитываются за ~5 мс (снимок графа — ещё ~20 мс). Время прогона определяют две вещи:

- **Запуск воркера под каждый скрипт: ~17 мс на узел** (Node, 2 ядра) и ~14–17 мс в Chromium. Для цепочки простых узлов это 99 % времени.
- **Complex Node в самом движке.** Каждая связь сверялась с каждой обёрткой (E × C): 1000 узлов, из них 990 в обёртках, считались 261 мс.

## Что изменено

**Скорость**

- Запуск скрипта: пока скрипты идут друг за другом (интервал до секунды), заранее запускается до двух свежих воркеров. Каждый скрипт по-прежнему получает свой воркер, поэтому глобальные переменные и таймеры одного скрипта не доходят до следующего (это проверяет новый тест). Простаивающие воркеры не держат процесс сервера и закрываются через 10 с; один скрипт без продолжения ничего лишнего не запускает. Результат: 50 узлов в потоках Node — 17,8 → 10,5 мс на узел; цепочка из 13 узлов в Chromium — ~14–17 → ~7 мс на узел.
- Связи через Complex Node ищутся по индексу портов, которые обёртки публикуют, а не перебором всех обёрток: 1000 узлов с 330 обёртками — 91 → 7 мс, с 990 обёртками — 261 → 11 мс. Без обёрток — без изменений (~5 мс).
- Обязательные входы обёртки проверяются один раз за запуск, а не при каждом запросе её выхода; `portDefault` вызывается один раз на порт; `Math.trunc` убран (после проверки типа `int` число уже целое); первые сообщения диагностики хранятся строкой, а не списками.
- В `routes-runs.js` ожидание `wait` (до 120 с) и отмена оставляли таймер жить после завершения запуска; теперь таймер снимается (`untilDone`).

**Упрощение**

- `evaluateGraph` был одной функцией с 125-строчным замыканием `value()`. Теперь: `wireGraph` (откуда берётся значение каждого входа), класс `GraphRun` (`value`, `complexValue`, `input`, `evaluate`, `runCode`, `account`) и тонкий `evaluateGraph`. Файл стал длиннее (230 → 322 строки: комментарии и разбиение), но самая длинная функция — 35 строк вместо 125, а пределы размера названы константами.
- Две копии `display()` и компиляции кода (воркер и встроенный запуск в `headless.js`) сведены к `displayText` и `compileScript` в `scripts.js`; воркер получает их текстом (`${displayText}`), поэтому двойное экранирование регулярных выражений в строке больше не нужно. Пределы 100 000 и 1 000 000 символов берутся из констант `evaluate.js`, а не повторяются числами.

**Ошибки**

- Порт с именем из `Object.prototype` (`toString`, `constructor`, `valueOf`…), для которого скрипт ничего не вернул, получал унаследованную функцию: и при чтении возвращённого объекта (`read[p.name]`), и при чтении кэша (`output in cache`). Для порта типа `any` функция уходила дальше по проводу. Теперь используется `Object.hasOwn`, узел получает обычную ошибку «did not return a value».

## Что сознательно не менялось

- Порядок вычисления входов — по очереди, в порядке портов. Параллельный обход независимых веток ускорил бы граф, но поменял бы порядок побочных эффектов скриптов и событий запуска.
- Один воркер на скрипт, без повторного использования: скрипт может оставить таймеры и глобальные переменные.
- Проверка длины цепочки (256) идёт раньше обращения к кэшу, как и было: узел из кэша на глубине 256 тоже отклоняется.
- Constructor по-прежнему выполняется заново на каждой фазе (OnStarted, OnCompleted): это описанное поведение узла.

- Дифференциальная проверка старого и нового движка на случайных графах (Complex Node, в том числе вложенные, типизированные значения, обязательные входы, падающие и «молчащие» скрипты, `display`, OnCompleted, несколько выходов, reroute, переполнение размера, отмена на n-м скрипте, режимы с `collect` и без): 4800 сравнений во встроенном режиме и 320 в потоках Node. Сравнивались результат, ошибки, статусы, `displays`, порядок вызовов хуков и скриптов, аргументы скриптов. Расхождений нет; проверка ловит намеренно внесённые ошибки в разборе обёрток.
- Chromium: цепочка из 13 узлов даёт верный результат, изоляция скриптов сохранена, ошибок консоли нет.

## Дополнение: выходы узла только через `node.output`

Раньше значение узла можно было отдать двумя способами: `return` из OnStarted (для одного выхода — само значение, для нескольких — объект по именам) и записью в `node.output`; «возвращённое значение побеждало». Теперь способ один: выходы — это то, что код оставил в `node.output` по имени выхода. То, что вернул обработчик, не используется.

- `phaseScript` для `on_started` всегда возвращает `node.output`; `runCode` читает выходы по именам из него. Правило «один выход — значение целиком» и ошибка «must return an object» убраны. OnCompleted получает выходы как `context.result`.
- Если узел ничего не записал в нужный выход, потребитель получает ошибку `OnStarted did not set node.output.<имя>` (раньше «did not return a value for …»). Так старый код с `return` не молчит, а подсказывает, что менять.
- Обновлены: узел по умолчанию, встроенные Script и Concat, ваша сохранённая копия Script (`data/library/resources.json`, редактор узла в `data/library/editors/`, workflow в `data/workflows/`), справка, README, `interface.md`, примеры в описании API, тестовые помощники `nodes.value` и `nodes.script`, тесты; добавлен тест «возвращённое значение не используется».
- Свои узлы с `return` в OnStarted нужно переписать вручную: `return x` → `node.output.<имя> = x`.
