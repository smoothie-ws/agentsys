# Ревизия проекта, 23 октября 2026

Задача: тотальная ревизия — найти и исправить ошибки и недочёты, сократить и оптимизировать код. Формат данных не менялся: ничего переносить не нужно.

Как проверялось: весь JS (модель, хранение, бэкенд, страницы, холст, инспектор, сервер) прочитан построчно; поверх этого — статический анализ на встроенном в Node `acorn` (неразрешённые имена, неиспользуемые объявления и члены), поиск повторяющихся блоков кода и неиспользуемых/перекрытых правил CSS, случайные последовательности вызовов API (фаззинг: 24 проектных и 21 «библиотечных» набор по 300 шагов с проверкой инвариантов после каждого шага) и замеры на графе из 600 узлов.

## Ошибки

- **Смена портов у Script оставляла «битый» граф.** Если у Script менялся тип входа или выхода, оставались связи с несовместимыми портами, привязки портов Custom Node к уже не подходящему порту и значения старого типа; граф получал диагностику «A saved connection has incompatible ports» / «Complex Node binding types do not match». Раньше убирались только связи с удалёнными входами. Теперь `Editor.pruneStale` после сохранения Script убирает несовместимые связи (повторяя проход, потому что тип Reroute зависит от подключённых проводов), значения, не подходящие новому типу, и устаревшие привязки. Нашёл фаззинг (8 наборов из 45).
- **Новая связь через Reroute могла сломать привязку порта Custom Node.** Reroute принимает тип входящего провода; привязанный к нему порт интерфейса другого типа становился несовместимым. `connections` теперь после добавления связей снимает такие привязки (`pruneBindings`). Проверка привязки вынесена в общую `bindingProblem` (`snapshot.js`) — раньше одно и то же условие было записано дважды, в диагностике и в очистке.
- **`Context.get` после `remove` возвращал удалённые данные.** Ключ, удалённый в рамках запроса, при повторном чтении снова загружался из базы и «воскресал», а удаление пропадало из записи. Теперь удалённый ключ остаётся удалённым до `set`.
- **Через маршруты проектов можно было переименовать, удалить и «наполнить» редактор Custom Node.** Для идентификатора `lib-…` (личный workflow узла Библиотеки) `DELETE projects/lib-…` стирал его документ, не трогая запись в Библиотеке, а `POST …/workflows` создавал неучтённые документы. Теперь изменяющие маршруты отвечают «A Custom Node is managed in the Library…»; чтение работает как раньше (его использует сам редактор).
- **Кнопка «Load available models» бросала необработанное исключение при неверном JSON в заголовках** — теперь ошибка показывается тостом.
- **Сервер отвечал 500 на запросы, которые заведомо неверны:** ошибочная `%`-последовательность в адресе, невалидный JSON, `null` или массив в теле `POST /__data`, неверная форма `set`/`remove`. Теперь 400. Файлы с нулевым байтом в пути не отдаются.
- **Evaluate: сообщение об ошибке узла без подписи** начиналось с `undefined: connect required input …`, потому что бралось `node.label`, а не уже вычисленная подпись (подпись, имя или тип). Кроме того, порт источника связи с устаревшим портом разрешался вне `try` и мог оборвать весь расчёт; теперь такая связь пропускается так же, как связь с устаревшей целью.

## Оптимизация (замеры на графе из 600 узлов)

| операция | было | стало |
|---|---|---|
| создать 600 узлов | 2,9 с | 1,2 с |
| перемещение узла | 11 мс | 4 мс |
| копировать и вставить 100 узлов | 441 мс | 46 мс |

- `buildSnapshot` больше не копирует глубоко каждый узел и группу (копия документа запроса и так личная) и умеет «снимок только структуры» (`structure`): без портов, связей и диагностики. Его используют перемещение, стили, выделение, сохранение групп и Complex Node, удаление группы — там нужны только существование, положение и стиль. `groups()` брал три снимка подряд — теперь один.
- `Context.get` сериализовал документ дважды при каждом чтении; теперь один раз.
- Удаление с «растворением» (`Dissolve`) искало исходящие связи перебором всех связей на каждом шаге обхода; теперь по индексу.
- `evaluateGraph` пересчитывал источник каждой связи для каждого Complex Node и искал участников по массиву; теперь один раз на связь и по `Set`.
- Не изменилось: пакетное добавление 400 связей одним вызовом (1,4 с) — каждое добавление меняет связность, поэтому снимок строится заново; интерфейс отправляет связи по одной.

## Лишний и дублирующийся код

- Две копии обхода предков группы (`isUnder` на холсте, локальная функция в `previewSVG`) заменены общей `isInside`.
- Итоги запуска (сводка, журнал, результаты Preview) собирались отдельно в `runAction` и `runFromCard`; теперь одна функция `runRecord`.
- `underFolder` (Библиотека) и `parentPath`/`underPath` (бэкенд) делали одно и то же; страница использует функции бэкенда.
- Мёртвые обработчики в инспекторе (`data-disconnect-edge`, `data-clear-value` нигде не создаются), три неиспользуемые переменные (`node` в `socketPoint`, `group` в `startResize`, `collapsed` в `Inspector.group`), константа `meaning`, `splice` с распаковкой всего списка в аргументы.
- CSS: повторные объявления (`.node.folded .fold`, `.subnav-row`, `transform/box-shadow` у `.subnav-item:hover`), правило `.frame .title`, целиком перекрытое последующим.
- Комментарии: в `editor.js`, `inspector.js` и `selection.js` заголовки разделов дублировались в двух стилях, а JSDoc оказывался отделён от своей функции.

Объём кода почти не изменился (JS 10 294 → 10 283 строки, CSS 3 561 → 3 550): повторов в проекте было мало (поиск почти одинаковых блоков находит один, он устранён), а исправления ошибок добавили столько же, сколько убрала чистка.
