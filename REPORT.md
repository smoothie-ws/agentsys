# Отчёт об укреплении AgentSys

Ветка `hardening/12h` от `main` (HEAD на старте: `a97bd91`). Safety-коммит —
`cafb1e8 chore: checkpoint before 12h hardening`; `main` не изменялся.
Работа заняла около 65 минут по времени коммитов (12:31–13:37), а не 12 часов:
почти все блоки уложились в таймбоксы, поэтому приоритетный список не пришлось
урезать.

## 3. Найденные и исправленные дефекты

| ID | Дефект | Исправление | Регрессия |
|---|---|---|---|
| C1 | `errors.host` оставался после успешного диспатча | сбрасывается после ответа хоста | `execution.test.js`: «a successful dispatch clears the host error…» |
| C2 | `node_ids: ["group:…"]` принимался и молча возвращал пустой результат | `checkRoots` отклоняет группы с 400 | «node_ids naming a group is rejected…» |
| C3 | Явный сигнал выключенного узла возвращал outputs прошлого запуска | выключенный корень не запускается и ничего не публикует | `disable.test.js`: «a disabled node does not report…» |
| C4 | Неограниченная рекурсия `execute` при частых view-update | предел 3 попытки и понятная ошибка | Детерминированно не воспроизведено за 15 мин; защита без отдельного теста, отмечено здесь |
| C5 | Сбой записи рантайма терял `dirty` и мог reject-нуть `wait:true` | ошибка сохраняется как `storage_error`, `dirty` остаётся, следующая запись повторяет; `wait:true` отвечает данными | «a failed runtime write is reported and kept…» |
| C5b | `dirty`, выставленный между последней проверкой цикла и `finally`, не записывался | `finally` запускает ещё одну запись, если изменений нет в полёте | Покрыто тем же тестом и сценарием эвикции (17-й рантайм) |
| C6 | Старт мог упасть на битом `.transaction.json`; запись переигрывалась дважды | чтение/валидация отделены, битый файл уводится в `.invalid`, повторная запись идемпотентна | `server.test.js`: «an interrupted commit is replayed once…» |
| V12 | `typeInUse` сериализовал все данные для каждого типа | один проход и Set на запрос | bench: 187 → 27 мс |
| V10 | 11 комментариев-разделителей в двойной кодировке | заменены на `// ----- … -----` | визуальная проверка, `npm test` |

Проверено и **не** подтвердилось: `group:` в `nodeMap` (после B1 отклоняется
корректно), 58 вариантов плохих тел/путей на HTTP (0 ответов 5xx), `null`-тела
(400 на сервере), path traversal (404/400), `If-Match` (409), падение плагинов
(существующие тесты).

## 4. Что откатили/не стали делать

- **Массовая консолидация CSS** (−400 строк). Точных дублей только 3 строки;
  19 повторных селекторов требуют анализа каскада и визуального стенда.
  Перенесено в `docs/ideas.md` (I-D3).
- **Рефакторинг `inspector.js`** (−100…−200 строк) и **`graph-nodes.js`**
  (−30…−60): высокий риск сломать DOM/bundle без браузерных тестов. Идеи I-C17,
  I-C18.
- **Кэш снапшота по `cursor`**: нет надёжной инвалидации при обновлении Library.
  Идея I-C15.
- **V2 (`syncRuntimeGraph` через `JSON.stringify`)**: не трогали, чтобы не
  менять семантику сравнения; идея I-C12.
- **Массовое удаление «мёртвого» кода**: скан 756 объявлений не нашёл ни одной
  неиспользуемой функции; удаление «на глаз» запрещено условиями.
- **Браузерный smoke**: Playwright в окружении не установлен, UI-файлы
  (`index.html`, страницы, навигация, горячие клавиши) не менялись. Ручной smoke
  остаётся за пользователем. По той же причине V5 (подпись узла без полного
  `JSON.stringify`) не имеет браузерного числа: изменение проверено статически
  (`node --check`, сохранение сравнения по ссылкам/строкам) и не меняет DOM.

## 7. Риски

| Риск | Оценка | Что сделано |
|---|---|---|
| Эвикция закрывает хост, а поздние события теряются | Низкий | эвикция только для idle без pending/saving/detached; тест восстановления state/outputs/displays |
| Коалесинг скрывает промежуточные значения | Низкий | первое изменение уходит сразу, последнее — на микротаске; `latest`/versions синхронны; flush перед done/pause/stop |
| Кэш компиляции удерживает память | Низкий | LRU 100 тел / 8 МБ; правка кода даёт новое тело, тест |
| `stopGraph` ждёт один тик перед `host.close()` | Низкий | нужен для передачи очереди событий; сетевые вызовы абортятся сразу, тесты Stop/сети зелёные |
| Транзакционный файл сочли «битым» при временной ошибке чтения | Низкий | парсинг/валидация отделены от записи; ошибка записи по-прежнему останавливает старт, чтобы не потерять данные |
| JS/CSS не сокращены до цели | Принято | честно зафиксировано, идеи на следующий цикл |

## 8. Итог

Ветка готова к ревью: 245 зелёных тестов, измеримые выигрыши по циклу, типам
Library, рантаймам и `data/`, закрытые P0/P1-дефекты. Цели по сокращению строк и
GET на 400 узлах не достигнуты — это ограничение выбранных безопасных изменений,
а не скрытая работа. Слияние в `main` и браузерный smoke — за пользователем.
